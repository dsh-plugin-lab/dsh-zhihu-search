# 决策：声明面承诺两族（并集），把 0.1.7 加回来（2026-10-10）

状态：生效

## 问题

2026-10-10 早先把声明面下限抬到 RC 线起点（只承诺一族），**这让一批真实使用者被判不兼容**——
他们停在 0.1.7 族的宿主上，抬下限之后他们的宿主不再落在声明区间里。维护者确认：这是
**真实的兼容修复**，不是预防性支持。

问题是：怎么同时承诺两族？

## 事实（本轮现查与实测，不抄进文档）

1. **npm 的预发布语义决定单区间罩不住**：一个预发布候选只有在区间里存在
   「**同一个 `major.minor.patch`、也带预发布段**」的比较子时才匹配。所以要同时承诺
   0.1.7 与 0.2.0 两族，单个区间**做不到** —— 必须用 `||` 显式枚举成并集。
2. **并集写法在 npm 上确实罩住两族**（实测 18 个受管包逐包 `npm view`）：
   `>=0.1.7-rc.1 <0.1.8-0 || >=0.2.0-rc.1 <0.2.1-0` 恰好罩住两族，0 缺失。
3. **上界写 `<0.1.8-0` 而非 `<0.1.8`**：两者在这个场景下行为一致，但 `-0` 是显式排除下一族的
   写法，意图更清楚（下一族的预发布不会被误收）。
4. **两族都能装、能构建、能跑测试**（实测，见「验收」）。

## 决策

1. `engines.dsh` 与全部 27 条 `@deepseek-ai/dsh-*` 声明 →
   **`>=0.1.7-rc.1 <0.1.8-0 || >=0.2.0-rc.1 <0.2.1-0`**（28 处同改，逐字相同）。
2. 换版语义随之改为「**保留旧族、只替换目标族**」，并新增 `--only`（测低族时临时收窄）——
   配套机制与实测见 [2026-10-10-swap-moves-family.md](2026-10-10-swap-moves-family.md)。
3. **巡检矩阵 = 声明面承诺哪些族就测哪些族**：承诺了 0.1.7 族，CI 就必须跑它（不跑等于假绿）；
   承诺一族 = 声明面加一族 + 矩阵加一行，两处都改完 CI 自动跑。之后宿主发新族**不**自动进矩阵，
   是否加承诺要人工决定。矩阵**不是**宿主发布日历。
4. **档位 patch**（维护者裁定）：只放宽声明面、不改行为，Q1/Q2 全否。但必须发版（声明在产物里）。

## 验收（本轮实测）

- 声明面在承诺线（`next`）上：`npm run check:declaration` rc=0（28/28 罩得住）。
- 0.2.0 族：清锁清树重装 → `npm run typecheck` 绿、`npm test` 313/313 绿。
- 0.1.7 族：`swap <旧RC族> --only <旧RC族>` 走完「改写→清锁清树→装→核对」，
  18 包 + 宿主本体全部落在目标族；随后 `npm run typecheck` 绿、`npm test` 313/313 绿。

## 替代方案（试过，为什么不选）

- **只承诺 0.2.0 一族**（维持 2.1.0 的下限）：不选 —— 那正是把 0.1.7 用户判不兼容的那版，是问题本身。
- **用单区间 `>=0.1.7-rc.1`（不带 `||`）**想同时罩住两族：不选 —— 实测它只匹配 0.1.7 族，
  罩不住 0.2.0 族（预发布元组对不上）。要承诺两族就必须枚举成并集。
- **去掉上界（`>=0.1.7-rc.1` 裸下限）**：与本仓「上界排除下一族」的既定策略冲突，且实测仍罩不住 0.2.0 族。
- **用 `||` 但不测低族**：不选 —— 0.1.7 族是对外承诺的一部分，不测就是假绿（用户那条要求也是这个意思）。

## 影响

- **使用者侧**：停在 0.1.7 族的用户重新被判为兼容（这正是本次修的）；停在 0.2.0 族的不受影响。
- **巡检矩阵多跑一族**：0.1.7 族那条是 record（只记录不阻断），它红要当回事（承诺坏了）。
- **固有代价**：跟多条预发布线就要付这份手动成本 —— 宿主发新族（新的 major.minor.patch）时，
  那条并集**不会自动罩住**它，要么加承诺（改声明面 + 改矩阵）要么它就不在承诺内。这条代价写明在
  [docs/PUBLISHING.md](../../docs/PUBLISHING.md) 的「兼容性」与 AGENTS 待办里。
- 配套的换包脚本族重构（`applyPlan` 支持 `||`、`--drop`、`--only`、按版本前缀定位族）另记 →
  [2026-10-10-swap-moves-family.md](2026-10-10-swap-moves-family.md)。
